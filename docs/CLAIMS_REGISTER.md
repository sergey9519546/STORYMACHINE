# Claims Register

Hand-maintained. Every user-facing empirical or guarantee claim the product
makes — anything that says the tool measures something, compares its output
to a human, promises determinism/reproducibility, promises privacy, or uses
an absolute word ("never", "always", "proven", "measured", "guaranteed") —
gets a row here, whether or not it currently holds up. **An unsupported claim
is listed as unsupported, not omitted.** This register exists because
`docs/audits/2026-09-02-retrospective/RETROSPECTIVE.md` finding #8 found that
`scripts/honesty-audit.mjs` caught banned *words*, not empirical *claims*: it
had no way to know that "reads your screenplay like a studio coverage
reader" was a promise about human agreement the product has never measured.

This file is enforced by `scripts/honesty-audit.mjs`'s claims lane (see its
"Claims-register lane" section) and exercised by
`tests/core/honesty-audit-claims.test.ts`:

- Every row with status `unsupported` or `retired` must **not** appear
  verbatim (whitespace-normalized) anywhere in the tracked tree outside this
  file and `docs/audits/**` (dated audit records — the retrospective is
  allowed to quote the problem it found).
- Every row with status `supported` must carry an evidence pointer that
  **exists on disk** (a `path`, or `path:line`).
- Every evidence pointer that names a LINE must carry a short quoted
  **anchor** — `path:line anchor:"some text from that line"` — and that text
  must occur within **±3 lines** of the line it names. Added 2026-09-12
  (`docs/audits/2026-09-12-adversarial/engine-logic.md` finding 11): until then
  "only the path is checked", so a line number pointing at the wrong code
  passed. Three files cited `server/nvm/analyze/doctor.ts:1892-1898` for this
  project's central negative finding about its own score while that comment had
  moved to `doctor.ts:2092-2093`, and a prior audit had already recorded the
  same anchor "FIXED in both places" — in the two places it looked at. Adding
  the anchors turned up **two more** stale line numbers nobody had reported:
  row 7's `ARCHITECTURE.md:267` (§8 is at :371) and row 10's
  `tests/core/coverage-html.test.ts:354` (the P3 verifiability comment is at
  :398). The anchor is what survives the drift: when code shifts, the quoted
  string moves with it, so a row needs editing only when its EVIDENCE changes.
  - A pointer citing a contiguous range (`a-b`) needs one anchor inside
    `[a-3, b+3]`. A pointer citing separate lines (`a,b`) needs one anchor per
    line — treating `1133,1528` as a single span would make the window 400
    lines wide and check nothing.
  - The `anchor:"…"` sigil is required rather than "the first quoted string in
    the cell", because several pointers already carry parenthetical notes
    containing quotes and backticks.
  - **Keep `;` out of a pointer's parenthetical notes.** Pointers are
    `;`-separated, so a semicolon inside a note splits it into a second,
    nonexistent pointer.
  - An anchor must be **at least 12 characters** and must match **exactly one
    line** inside its own ±3 window. `anchor:"e"` satisfied `String.includes`
    on almost any line and passed the first version of this rule; a substring
    matching three lines of the window identifies nothing either. Both halves
    are needed — the rule caught one of its own author's anchors
    (`"report.plainSummary"`, three matching lines) on its first run.
  - The **"Where it appears" column is checked too**, for every row that is not
    `retired` or `unsupported`. It was exempt for one day, on the reasoning that
    "several of its line numbers are historical by design — rows 1, 2 and 25 are
    `retired`". That was true of three rows and **false of fifteen**: excluding
    retired rows, 15 of the 18 remaining appears-column pointers were stale by
    6 to 1550 lines (row 9 cited `ScriptDoctorPanel.tsx:3443` for copy at
    `:4993`; row 20's appears cell still said `ARCHITECTURE.md:305` while the
    same row's evidence cell had just been corrected to `:414`, one cell to the
    right). All 18 now carry anchors, and each corrected cell records the line
    it used to cite. The carve-out is now exactly what its reason describes: a
    `retired` or `unsupported` row's location records where wording USED to be,
    so it is expected not to resolve.
- A curated list of empirical-claim phrases (below) is banned anywhere in
  `src/**`, `README.md`, `ARCHITECTURE.md`, `NORTH_STAR.md`, `ROADMAP.md`,
  `docs/PATH_TO_EXCELLENCE.md`, `index.html` **unless** the exact sentence
  containing the phrase is registered here with status `supported` at that
  same file. The general `docs/**` exemption in `honesty-audit.mjs` does
  **not** cover these six named orientation docs for this lane — they are
  scanned like `src/**`.

## Evidence types

- **measured-in-repo** — a runnable test in this repo asserts the claim
  (cite the test file, and the `it(...)` block if it helps).
- **measured-owner-local** — measured by a documented owner-run process
  outside CI (e.g. `npm run measure-real` against the local real-script
  corpus) with a receipt committed to the repo.
- **human-agreement** — would require independent human readers agreeing
  with the tool's output. **This repo has none of these today** — see
  `ARCHITECTURE.md:305`'s own "Not yet proven by default CI: human agreement
  with scores" and the P1 program in `ROADMAP.md` §3, which is what would
  eventually produce this evidence.
- **none** — no evidence exists; the claim is not testable as stated, or
  nobody has run the measurement yet.

the control genuinely cannot reach, which is the part of an honest deletion
promise that is easiest to leave out.
