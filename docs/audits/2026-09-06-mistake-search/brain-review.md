## 3. Findings

### 3.1 `npm run check-brain` silently checks nothing on a path containing a space — BLOCKING

`scripts/brain-graph.mjs:252`:

```js
if (import.meta.url === `file://${process.argv[1]}`) {
```

`import.meta.url` percent-encodes; `process.argv[1]` does not. Reproduced, on a `git archive` copy
of this exact tree placed at a path whose only difference is one space in a directory name, with a
deliberately broken `[[No Such Note]]` appended to `Glossary.md`:

```
$ node scripts/brain-graph.mjs --check ; echo "exit=$?"
exit=0                      # no output at all — main() never ran
$ node scripts/brain-graph.mjs      ; echo "exit=$?"
exit=0                      # nothing written; the stale graph stays stale
```

```
argv1        = …/space copy/scripts/probe-entry.mjs
import.meta  = file:///…/space%20copy/scripts/probe-entry.mjs
equal?       = false
```

So on such a checkout the new CI-blocking step exits 0 while an unresolved wikilink AND a stale
export are both present, and `npm run brain` reports success while writing nothing — an author then
commits a stale graph believing they regenerated it. This is the vault's own
`Patterns.md:53-65` class, "a gate that cannot fail", introduced by the same commit that documents it.
Blast radius is bounded (GitHub runners have no space in the path, and `brain-coverage.test.ts`
imports `buildGraph()` directly so `npm test` still catches both conditions), but the repo's own
Windows/OneDrive checkout hazard is called out in CLAUDE.md and OneDrive paths routinely contain
spaces. Every other script in `scripts/` already uses the space-safe idiom —
`report-unverified-gates.mjs:249`, `discharge-obligations.mjs:636`, `lock-auc24.mjs:281`,
`check-doctor-output-identity.mjs:502-503`, `check-scoring-receipt.mjs:832-833` — so this is a
one-line "match surrounding patterns" fix:

```js
if (process.argv[1] && pathToFileURL(path.resolve(process.argv[1])).href === import.meta.url) {
```

## 6. `00 Home.md` — would a new agent know what to do next?

Mostly yes, and it is better than CLAUDE.md at the "what is this" question. It opens with the product
thesis, states the One Bet with its numbers, gives the current phase with per-phase status, and ends
with a "Start here, by question" list that routes every question type to a named note. The
owner-only list is easy to find — its own `## Owner-only list` section linking `[[Owner - Index]]`,
and a routing line in the question list.

The gap is the literal question "what do I do next?". CLAUDE.md answers it with
`docs/PATH_TO_EXCELLENCE.md` ("current lane sequence and live status"); Home cites that file only in
its Sources block and its phase paragraph, and has no "the next work is X" line and no note type for
the lane sequence. An agent landing on Home learns the phase and the standing constraints, then has
to leave the vault to find the queue. Adding one line under "The current phase" — the live lane
sequence, its file, and a pointer that the owner list is the other half of the queue — would close it
without a new note type.
