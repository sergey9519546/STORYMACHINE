# Audit — 2026-09-18 Node 24

**Directory:** `docs/audits/2026-09-18-node-24/` — one lane record for
`lane/node-24`, branched from `8b6a60c1`. CI and the Docker image move from
Node 22 to Node 24 LTS, the runtime the owner's machine moved to the same day.

## The three predicted risks

**The voice-weight bound.** `MAX_FOUNTAIN_VOICE_ELIGIBLE_DISTINCT` is derived
from a table measured on Node 22. Two same-day pairs of calibration runs,
Node 22 against Node 24, all on one CPU model, measured Node 24 **cheaper on
every row of both pairs** (median ratio about 0.87). The table was **not**
re-locked. A Node 24 lock from those runs would have cut the constant from
80 to 70, and the reason would have been which CPU the runner drew, not
anything Node 24 did. On that CPU the Node 22 control could not derive any
cast at all. Whether to re-lock anyway, so the recorded runtime matches the
enforcing one, is left to the owner.

**The image.** Every node:22-alpine measurement from
[[Audit - 2026-09-18 Edge Image]] was repeated on node:24-alpine and matched
byte for byte. python3 and make are still required, and g++ is still
headroom. better-sqlite3's single N-API prebuild loads under the new module
ABI. The full image builds and
boots, and SQLite writes as the non-root user.

**`--experimental-strip-types`.** Node 24 accepts it silently. It stays,
because the engines floor (22.13) still needs it.

## The risk nobody predicted

Node 23 changed node:test's default reporter from TAP to `spec` for piped
output. CI's failure summary reads `npm test`'s output as TAP, so on Node 24
a red run would still have gone red, but its summary would have said "no
`not ok` lines found". `run-tests.mjs` now names the reporter, and
`tests/scripts/test-reporter.test.ts` was shown red on unfixed input first.

The standing lesson is [[Patterns]]-shaped: **a default you inherit is a
dependency you did not write down.** Nothing in the repository said "TAP".
The format came from the runtime, and the runtime changed.

## Found, not fixed

- The container `HEALTHCHECK` fails on a Docker host that maps `localhost` to
  `::1`, because the server binds IPv4 only. The node:22 image from `main`
  fails the same way. This is pre-existing and filed separately.
- A fresh `npm ci` fails on the owner's Windows machine because no Visual
  Studio instance is registered and node-gyp needs one even to do nothing.
  Node 24 did not cause it.
